1. Contexte et vision

1.1 Présentation du projet

Monsite.ma est une plateforme SaaS marocaine qui permet à des vendeurs (sociétés ou particuliers) de créer et gérer leur propre boutique e-commerce, accessible via une URL unique sous forme de sous-domaine (ex : vendeur1.monsite.ma).

1.2 Positionnement

Monsite.ma se positionne comme un hébergeur de mini-boutiques, et non comme une marketplace. Chaque boutique est indépendante : design propre, catalogue propre, moteur de recherche propre, clients propres. La plateforme mutualise uniquement l'infrastructure, le code, la base de données et la maintenance.

Ce que Monsite.ma n'est PAS :
  • ❌ Une marketplace (pas d'annuaire central, pas de moteur global)
  • ❌ Un intermédiaire financier (aucun flux d'argent ne transite par la plateforme)
  • ❌ Un logisticien (le vendeur gère sa propre livraison)
  • ❌ Un gestionnaire de stock (le vendeur est seul responsable)

1.3 Objectif du MVP

Livrer une première version fonctionnelle permettant à un vendeur de :

  1. S'inscrire, payer son abonnement annuel et uploader son KYC
  2. Préparer sa boutique (produits, template, paiements) en mode invisible
  3. Être validé manuellement par le super-admin
  4. Vendre en ligne (paiement en ligne ou COD)
  5. Gérer commandes, stock, avis et statistiques depuis son backoffice

2.2 Modèle juridique

Point critique : Monsite.ma est un prestataire technique. Elle ne vend aucun produit, ne détient aucun stock, n'encaisse aucun paiement client final. Les paiements en ligne sont opérés par les PSP configurés par chaque vendeur (CMI, Stripe, PayPal). Le paiement à la livraison est géré exclusivement par le vendeur.

3.2 Architecture multi-tenant

Chaque boutique est identifiée par son sous-domaine. Le middleware Next.js détecte le sous-domaine dans la requête HTTP et charge la configuration de la boutique correspondante. 

Requête : https://vendeur1.monsite.ma/produit/123
     ↓
Middleware Next.js → extrait "vendeur1"
     ↓
Requête DB : SELECT * FROM shops WHERE subdomain = 'vendeur1'
     ↓
Charge template + produits + config paiement de la boutique
     ↓
Rendu SSR de la page boutique

3.3 Environnements

  • Development : local
  • Staging : staging.monsite.ma + *.staging.monsite.ma
  • Production : monsite.ma + *.monsite.ma

5. Modules fonctionnels

Module 1 — Inscription, KYC et validation Critique

1.1 Parcours vendeur

  1. Landing page monsite.ma/inscription : formulaire en 3 étapes
  2. Étape 1 — Compte : email, mot de passe, téléphone, nom, type (société / particulier)
  3. Étape 2 — Boutique :
    • Société : nom boutique (= nom RC), slug auto-généré, upload RC, ICE, adresse, ville
    • Particulier : nom boutique libre, slug auto, upload CIN, adresse, ville
  4. Étape 3 — Paiement : 1800 DH/an (CMI ou virement) + option domaine custom (+200 DH)
  5. Post-paiement : statut "en attente KYC", accès backoffice brouillon
  6. Validation : sous 48h par super-admin → boutique activée ou rejetée

1.2 File d'attente super-admin

Écran admin.monsite.ma/validations avec :

  • Liste filtrable (statut, type, date, ville)
  • Fiche détaillée : infos vendeur + visualiseur KYC + checklist 5 points
  • Actions : Valider / Demander complément / Rejeter

1.3 Checklist de validation (5 points)

  • Nom boutique correspond au RC (sociétés)
  • RC valide (date, numéro, lisibilité)
  • ICE renseigné et cohérent
  • Sous-domaine disponible et conforme
  • Aucun signalement (nom suspect, doublon, activité illégale)

1.4 Workflow des statuts

[En attente] → [Validé] → Boutique activée
     ↓
[À compléter] → Vendeur re-uploade → [En attente]
     ↓
[Rejeté] → Remboursement auto sous 7j → [Remboursé]

1.5 Règles de gestion

  • Unicité : nom boutique, slug, email
  • Délai validation : 48h ouvrées — alerte admin si dépassé 36h
  • Remboursement sous 7 jours si rejet définitif
  • Suspension après validation (fraude) → page "site en maintenance"
  • Renouvellement : relance J-7, suspension auto J-0, suppression J+30

Module 2 — Gestion produits Critique

  • CRUD produit (titre, description, prix, promo %, stock, images, catégorie imposée)
  • Variantes : liste défilante, visible uniquement sur la fiche produit front
  • Images : 5 max, 0.5 Mo chacune, compression auto côté serveur (WebP + 3 tailles)
  • Catégories : imposées par la plateforme (10 catégories niveau 1 validées)
  • Import/Export CSV : modèle fourni par la plateforme, gestion des erreurs ligne par ligne
  • Backoffice : pagination 50/page, recherche, filtres, actions groupées (prix, publication, suppression)

Module 3 — Templates et personnalisation Haute

  • 5 templates figés (structure non modifiable)
  • Personnalisation : logo, couleurs, bannière, contenu texte, images
  • Changement de template possible à tout moment sans perte de contenu
  • Responsive mobile obligatoire (priorité mobile Maroc)

Module 4 — Tunnel de commande et paiements Critique

4.1 Tunnel

Panier → Coordonnées → Livraison → Paiement → Confirmation

  • Achat invité autorisé (désactivable par le vendeur)
  • Compte créé automatiquement après commande (email + mot de passe)
  • Panier persistant (cookie)
  • Mode de livraison imposé par le vendeur

4.2 Multi-PSP dans le backoffice vendeur

Page "Paiements" avec 4 onglets :

PSPConfiguration
CMIClé marchand + clé API + test de connexion
StripePublishable key + Secret key + test
PayPalClient ID + Secret + mode sandbox/live
VirementRIB, nom bénéficiaire, instructions, référence commande

Activation sélective par PSP. Clés chiffrées AES-256 en base.

4.3 COD (paiement à la livraison)

  • Confirmation téléphonique obligatoire avant expédition
  • Statut commande mis à jour manuellement par le vendeur

Module 5 — Commandes et stock Haute

  • Statuts : En attente → Confirmée → Expédiée → Livrée → Annulée / Retour
  • Décrément automatique du stock à chaque commande
  • Alertes rupture (seuil configurable par produit)
  • Bon de livraison + facture générés automatiquement (PDF)
  • Retours/remboursements gérés dans le backoffice
  • Création manuelle de compte client (pas de commande manuelle)

Module 6 — Compte client Haute

  • Achat invité (email + téléphone + adresse)
  • Création auto du compte après commande (mot de passe par email)
  • Réclamation du compte possible plus tard
  • Espace client : historique commandes, suivi, adresses

Module 7 — Avis clients Moyenne

  • Modération par le vendeur avant publication
  • Réponse du vendeur possible sous l'avis
  • Note globale de la boutique affichée
  • Filtres côté client : note, date, avec photo

Module 8 — Notifications email Moyenne

  • Provider : Resend au lancement (3000 emails/mois gratuits)
  • Préférences configurables (vendeur + client)
  • Vendeur : nouvelle commande, rupture stock, avis client, paiement reçu
  • Client : confirmation commande, expédition, livraison

Module 9 — Statistiques Moyenne

  • KPIs : CA, nb commandes, panier moyen, produits vus, taux de conversion
  • Périodes : jour / semaine / mois / année avec comparatifs
  • Export CSV

Module 10 — Multi-utilisateurs Moyenne

  • 2 utilisateurs max par boutique
  • Rôles : propriétaire (tout) + employé (produits + commandes)
  • Employé : pas d'accès aux statistiques financières

Module 11 — Facturation annuelle Critique

  • 1800 DH/an — CMI ou virement
  • Facture PDF automatique (Resend)
  • Relance J-7 avant expiration
  • Suspension auto à J-0 (page maintenance)
  • Suppression à J+30 (données conservées 90 jours)

Module 12 — Domaine custom Basse

  • Sur demande + 200 DH/an
  • Vendeur achète son domaine chez un registraire
  • Pointe un CNAME vers vendeur1.monsite.ma
  • SSL Let's Encrypt automatique

7. Sécurité et conformité

7.1 Sécurité technique

  • HTTPS obligatoire (SSL auto via Let's Encrypt sur tous les sous-domaines)
  • Chiffrement AES-256 des clés API PSP en base de données
  • Hashage bcrypt (coût 12+) des mots de passe
  • Rate limiting sur les endpoints sensibles (inscription, login, paiement)
  • CSRF protection sur tous les formulaires
  • Validation stricte des inputs (Zod ou similaire)
  • Sauvegardes quotidiennes de la base de données (rétention 30 jours)
  • Logs d'audit pour les actions super-admin (validation, rejet, suspension)

7.2 Conformité

  • Conformité loi 09-08 (protection des données personnelles au Maroc)
  • Déclaration CNDP obligatoire avant lancement
  • Mentions légales sur monsite.ma (CGU, CGV, politique de confidentialité)
  • Conservation des documents KYC : 90 jours après rejet, durée légale après validation

7.3 Isolation des données (multi-tenant)

Point critique : chaque requête en base doit être filtrée par shop_id pour empêcher tout accès croisé entre boutiques. Une couche d'abstraction (repository pattern) est fortement recommandée.
